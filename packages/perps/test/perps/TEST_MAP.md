# Perps test map

This is a reference index for finding executable examples of protocol behavior. Start with the
[protocol overview](../../README.md), then the [accounting specification](../../ACCOUNTING_SPEC.md) and
[security model](../../SECURITY.md). Tests provide evidence for those rules; passing tests are not a proof that
all inputs or integrations are correct. The [invariant guide](invariant/README.md) explains the stateful models.

## Finding the right evidence

- **Independent model:** expected values advance from action inputs and a separate ledger.
- **Direct expected behavior:** explicit amounts, boundary values, custody changes and rollback checks.
- **Parity:** agreement between production views, planners and execution; shared code can share a bug.
- **Synthetic state:** storage mutation or privileged-component impersonation isolates a behavior without proving
  that a public user can reach that state.
- **Full-stack execution:** real package contracts with the stated token/oracle doubles; external services remain separate.

The tables group representative tests by topic. Follow a file link for its companion cases and fixture setup.
An exact name can be passed to Forge's `--match-test`; use `--match-path` as well when names are inherited or repeated.
USDG amounts use six decimal places, so a one-atom boundary means one micro-USDG.

## Close integration checks

The [close-settlement coverage](#close-settlement-and-zero-execution-bounties) checks closes without added USDG, commitment
carry, preview/execution agreement, reservations and terminal receipts. Complementary
[partial-close health tests](accounting/close/PartialCloseHealth.t.sol) isolate synthetic planner snapshots, while
[protection/liquidation batch tests](spec/keeper/PositionProtectionLiquidationBatch.t.sol) exercise their combined
lifecycle. [Direct-close](gas/DirectCloseGas.t.sol) and [preview](gas/CfdClosePreviewGas.t.sol) benchmarks add production
gas/runtime gates. These identify available checks; they do not assert that a release has run or passed them.

The SDK's [keeper tests](../../../perps-aa-client/test/keeperExecution.test.ts) check zero-funding owner-account
wrapping, queue-head classification, execution/trigger fee quotes and native transaction calldata.
[Terminal-history tests](../../../perps-aa-client/test/terminalHistory.test.ts) check authenticated receipt decoding
and reject altered context or economics. The [compatibility suite](../../../perps-aa-client/test/compatibility/README.md)
pins current and archived ABI boundaries, including the replay-aware close-preview result. These client encoding
and authentication checks do not establish deployed economic behavior.

Run the consuming frontend, keeper and protection-worker tests against the intended contract graph. The
[frontend acceptance checks](../../CLOSE_PREVIEW.md#acceptance-checks) cover replay handling, commitment carry counted
once, bound/mode enforcement, stale-review rejection and confirmation from verified terminal evidence. Core tests
cannot establish that an external client has implemented those behaviors or uses the matching ABI.

The native fallback fork above exercises the owner of the original smart account with no added USDG. It does not
exercise UserOperation validation, a bundler, paymaster, protocol API or public-chain transaction. The
[historical close regression](fork/HistoricalCloseRegression.t.sol) and
[sponsored-close fork](fork/CfdSponsoredCloseFork.t.sol) use archived deployment interfaces; they do not qualify the
current request/preview ABI. Fork prerequisites and their CI selection are listed under
[external integration limits](#external-integration-limits).

From the repository root, focused checks are:

```bash
FOUNDRY_VIA_IR=true forge test --offline --root packages/perps \
  --match-path 'test/perps/differential/CfdClosePreview.t.sol'
FOUNDRY_VIA_IR=true forge test --offline --root packages/perps \
  --match-path 'test/perps/accounting/close/DepositFreeClose.t.sol'

# Requires NATIVE_CLOSE_FORK_RPC_URL with access to the pinned block.
forge test --offline --root packages/perps --match-path 'test/perps/fork/NativeCloseFallback.t.sol'

# Requires the SDK dependencies installed with npm ci in packages/perps-aa-client.
npm --prefix packages/perps-aa-client test -- \
  test/keeperExecution.test.ts test/terminalHistory.test.ts test/compatibility.test.mjs
```

Focused passes are not a complete release record. Follow [running and replaying](#running-and-replaying) and the
[review guide](../../SECURITY.md#review-guide) for recorded source/build configuration, production gates, campaign
budgets, outcomes and durable artifacts. Missing prerequisites, skipped tests, interrupted runs and partial shards
remain incomplete validation. Old gas measurements and successful runs do not qualify changed source or tuples.
Deployment bindings, client builds, funded operators, failover drills and operating runway belong in the
[deployment guide](../../DEPLOYMENT.md); local checks do not establish their public-chain availability.

## Running and replaying

Run from the repository root with Foundry and Solc 0.8.35 available. The recorded runners use `--offline`, so the
compiler must already be cached. CI currently installs Foundry 1.5.1.

```bash
# Validate documentation links, runner behavior and test inventory without running Solidity suites.
make check-perps-tests

# Complete non-fork suites at local, CI and multi-seed audit budgets.
make test-perps-quick
make test-perps-ci
make test-perps-audit

# Run only configured package fork integrations.
make test-perps-fork

# Focused correctness run with the package configuration.
FOUNDRY_PROFILE=quick forge test --offline --root packages/perps \
  --no-match-path '**/fork/**' --match-contract '^PerpIndependentClaimInvariantTest$'

# Inspect one physical shard without compiling or executing it.
PERPS_SHARD_LIST_ONLY=1 bash scripts/run-perps-package-tests.sh 0 4

# Replay one PR shard with the CI seed.
PERPS_SHARD_MODE=pr FOUNDRY_PROFILE=ci FOUNDRY_FUZZ_SEED=0xdeadbeef \
  bash scripts/run-perps-package-tests.sh 0 4
```

| Profile | Fuzz runs | Invariant runs | Depth | Default use |
| --- | ---: | ---: | ---: | --- |
| `quick` / default | 256 | 16 | 128 | Local iteration |
| `ci` | 2,000 | 32 | 256 | PR and post-merge |
| `audit` | 20,000 | 256 | 1,000 | Nightly and pre-audit |

The quick/CI runners batch non-fork entrypoints before any executable discovery. Each serial batch contains at
most four files and uses one Forge thread. Discovery compiles that batch once without via-IR, then partitions the
executable inventory into production via-IR gates and non-via-IR correctness tests. Empty partitions are recorded
without compilation or execution. The selection checker rejects missing, duplicate, or unexpected tests and source
entrypoints; a successful aggregate requires every assigned file and every batch to complete. PR CI applies the
same batching inside its four physical shards. Local `make test-perps` and `make test-perps-ci` use it for the full
non-fork inventory. Profile budgets and seeds are unchanged.
Post-merge/deep shards use production via-IR throughout, compiling and running at most four test entrypoints per
serial batch with one Forge thread. Shared fixtures stay at stable paths; each batch records its exact executable
selection and results. The shard fails unless every assigned entrypoint completes successfully. Set
`PERPS_COMPILE_BATCH_SIZE` to a positive integer to change this memory bound; replay records that setting.
The audit target and manually dispatched deep workflow
run seeds `0xdeadbeef`, `0x1` and `0x2`; nightly seeds derive from the workflow run ID. Environment overrides are
captured in the effective configuration.

Recorded runs write to `artifacts/perps/` by default; set `PERPS_ARTIFACT_DIR` to change the destination. Evidence
includes revision/working-tree state, toolchain, effective configuration, discovered tests, results, durations,
invariant counters, failure corpora, run status and `replay.sh`. Replay from the repository root at the recorded
revision, including its recorded dirty-tree patch when applicable. Restore saved `corpus/fuzz` and
`corpus/invariant` to the recorded persistence paths for corpus replay. Shard replay reconstructs the temporary test
tree. A historical passing report attests only its recorded source and configuration.

Coverage is a separate instrumented lane. Its inventory excludes RPC tests, fuzz/stateful campaigns, gas/size gates
and named instrumentation-sensitive batch scenarios; these still belong to their ordinary execution lanes.
`--ir-minimum` can emit missing-source-anchor warnings with the pinned toolchain, so LCOV is partial instrumentation
evidence rather than proof of complete line/branch coverage.

## External integration limits

The fork runner recognizes three independent settings:

| Setting | Suite |
| --- | --- |
| `SPONSORED_CLOSE_FORK_RPC_URL` | `fork/CfdSponsoredCloseFork.t.sol` |
| `CLOSE_REGRESSION_ARCHIVE_RPC_URL` | `fork/HistoricalCloseRegression.t.sol` |
| `NATIVE_CLOSE_FORK_RPC_URL` | `fork/NativeCloseFallback.t.sol` |

Configured suites require their pinned chain, block, code and fixtures and may not silently skip. Unconfigured
suites are recorded as **not run**; the wrapper exits with an error when none is configured. The deep CI workflow
supplies all three settings from repository secrets; it qualifies native-close fallback only when that secret is configured.

Root `test/fork/PerpsFork.t.sol` uses real USDC through the token-neutral API with a controllable oracle. Root `test/fork/PythRealUpdateFork.t.sol`
and the synchronization, live-basket, LP epoch and liquidation forks exercise real Pyth with signed fixtures. These
root integrations are outside the package-only `make test-perps-fork` runner. Use `make test-perps-fork-all` for every
root, package and paymaster perps fork lane, with `MAINNET_RPC_URL` and `ARB_SEPOLIA_RPC_URL` set. It fetches the fresh
Pyth fixture (optional `PYTH_API_KEY`), enables isolated oracle scenarios, supplies archive aliases and rejects missing
entrypoints, inherited selection filters, empty selections or skipped tests. The default artifact directory is
`artifacts/perps/integration-forks`; `PERPS_ARTIFACT_DIR` overrides it. Each lane records effective compiler settings,
discovered tests and results, and `summary.json` aggregates the run. Generated replay scripts restore the saved public
`pyth-fixture.json`; direct runs can use `PERPS_PYTH_FIXTURE` instead of fetching a new update. The offline [Across fixture](../fixtures/across-direct-funding/README.md)
validates pinned handler execution with a mock token; it does not validate a live quote or bridge fill.

No single campaign models every oracle, governance, fee, insolvency and LP lifecycle combination. Keep successful
public reachability, relevant boundary/failure outcomes and checker sensitivity alongside each critical rule.
Update this map when those assertions change; use the [invariant guide](invariant/README.md) for model domains.
